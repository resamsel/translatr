## 3. Root routing: wildcard and forbidden

- [x] 3.1 Add a trailing `{ path: '**', redirectTo: '' }` route; leave `forbidden` unguarded. Verify with a test that navigating to a bogus path as a non-admin ends on `/forbidden` and as an admin ends on the dashboard. — done, with deviation: the wildcard is the last entry of the `routes` array in `dashboard-page-routing.module.ts`, NOT `app-routing.module.ts`. `app-routing.module.ts` runs `RouterModule.forRoot` and is loaded before the feature modules, so a `**` there sorts ahead of the shell's real `path: ''` (and the login module's) and shadows every route. Keeping it at the end of the last feature routing module keeps it last in the flattened config. `DASHBOARD_ROUTES` (= `routes`) is only read as `routes[0]` by the dashboard component, so the extra entry is inert there. `forbidden` stays unguarded in `app-routing.module.ts`.
